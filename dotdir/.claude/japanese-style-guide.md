# 日本語スタイルガイド（記録・育成ファイル）

Claude Code の日本語出力品質を律する常駐ルール。CLAUDE.md から `@japanese-style-guide.md` で参照され、常にコンテキストに載る。ユーザーが表現へ不満・言い換え要望を示したら、応答の前に「## 禁止→推奨 対応表」へ1行追記する。

## 一般ルール

- **文体**：です/ます体で統一。結論ファースト、前置き・段階報告は不要。
- **英語混入の線引き**：
  - ✅ 許可：コード識別子（変数/関数/ファイルパス）、確立した技術用語（API, git, commit, hook, MCP, PR 等）、製品名・固有名詞
  - ❌ 禁止：日常語の英語化（"Let me...", "First,", "Note that", "OK", "Done" 等を地の文に）、理由なきカタカナ英語、英文の地の文
- **崩壊出力の禁止**：ツール呼び出しマークアップ（`invoke` / `parameter` タグ等）を地の文に書かない。ツール呼び出しは正規チャネルで行う。
- **冗長さの回避**：直訳調・二重表現・冗長な敬語を避け、簡潔に書く。

### ドメイン英単語の裸書き（status 値・操作名・信号名を日本語名詞の代わりに使わない）

- ❌ ドメイン英単語（status 値・サブコマンド名・信号名等）を地の文へ裸で書く → ✅ 日本語訳を主とし、識別子として指す必要がある初出のみ「訳語（`識別子`）」形式。以降は訳語のみ（英語混在は認知負荷が高い、ユーザー指摘 / 2026-07-02）
- ❌ 地の文の「candidate」「active」 → ✅ 「候補」「正式」。enum 値として指す時のみ `candidate` / `active`（2026-07-02）
- ❌ 地の文の「promote」「promote 待ち」 → ✅ 「昇格」「昇格待ち」。tool 名参照は `promote_knowledge` と backtick 表記（2026-07-02）
- ❌ 地の文の「dedup」「dedupe」「重複 skip」 → ✅ 「重複排除」「重複スキップ」。識別子 `dedupe_key` は例外（2026-07-02）
- ❌ triage 信号名の裸列挙「impact/contradiction/corroboration」 → ✅ 「影響度・矛盾・裏付け」。信号 ID として指す時のみ backtick（2026-07-02）
- ❌ 地の文の「raw」「入口 filter」「state 前進」「scan/apply」 → ✅ 「原文」「入口の絞り込み」「処理済み記録の前進」「点検（`scan`）/適用（`apply`）」（同型の違反、2026-07-02）

### 医学・統計ドメイン語の英語裸書き（確立訳語があるものは日本語にする）

- ❌ 地の文の「dose-response」 → ✅ 「用量反応関係」（統計・疫学の確立訳語 / 2026-07-06）
- ❌ 地の文の「mobility」「mobility-trajectory」 → ✅ 「移動能力」「移動能力の軌跡」（歩行・移動の確立訳語。カタカナ「モビリティ」より明確 / 2026-07-06）
- ❌ 地の文の「qualified GO」 → ✅ 「条件付きで前進（可）」。判断語として指す初出のみ `GO`/`no-go`（"qualified"＝条件付き を訳す / 2026-07-06）
- ❌ 地の文の「incident frailty」 → ✅ 「新規フレイル発症」（"incident"＝新規発症。「フレイル」カタカナ単体は日本老年医学会採用の確立訳語で可 / 2026-07-06）
- ❌ 地の文の「frailty transition」 → ✅ 「フレイルへの移行」（robust→prefrail→frail の状態移行 / 2026-07-06）
- ❌ 地の文の「前フレイル」 → ✅ 「プレフレイル」（ユーザー指定。J-CHS の robust/prefrail/frail は「正常/プレフレイル/フレイル」で統一 / 2026-07-06）
- ❌ 地の文の英語副詞「meaningfully」「significantly」等 → ✅ 日本語（「有意に」「意味のある形で」「実質的に」）。統計的有意は「有意」、実質的改善は「実質的に」（2026-07-06）

### ユーザー指定の語彙（訳さず英語のまま使う）

- ❌ 「部品」（設計・実装の構成単位の訳語）→ ✅ 「Part」。構成単位は訳さず Part と呼ぶ（ユーザー指定 / 2026-07-06）
