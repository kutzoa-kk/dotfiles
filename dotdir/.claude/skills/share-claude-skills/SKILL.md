# Claude Code と Codex のスキル共有

この dotfiles の `dotdir/.claude/skills/` を共有元とし、Codex・agy が読む `~/.agents/skills/` にスキル単位でリンクする。コピーして二つの正本を作らない。Claude は既存の `~/.claude/skills` から同じ実体を読む。

## 確認

リポジトリルートで次を実行する。スクリプトは読み取り専用で、Python 標準ライブラリだけを使う。別の作業ディレクトリからは絶対パスで実行してよい。

```bash
python3 dotdir/.claude/skills/share-claude-skills/scripts/check_sharing.py
```

- `shared`: Codex のユーザー・リポジトリの共有先から同じ実体を参照している。
- `legacy_only`: `~/.codex/skills`（または `$CODEX_HOME/skills`）だけに同じ実体がある。現行の共有先ではないため、移行候補として扱う。
- `unshared`: 共有先に同じ実体がない。**共有可能と判定した意味ではない**。
- `conflicts`: 同名の別実体、通常ファイル、またはリンク切れが共有先にある。共有済みと併存する場合も報告する。
- `broken_sources`: 共有元にあるリンク切れなど。`SKILL.md` のない補助ディレクトリと隠しディレクトリは対象外。

起動時は未共有・競合・リンク切れ・旧配置だけのスキルを件数と代表例で短く報告する。全スキルの本文を読み込んだり、共有可否を一括判定したりしない。対象がなければ正常を一言伝えて、本来の依頼へ進む。

これはファイル配置の確認であり、Codex の設定による無効化や実際のスキル一覧への反映までは判定しない。プラグイン cache・システムスキル・他プロジェクトのスキルは対象外。

## 共有を依頼されたとき

1. 対象の `SKILL.md` と、実行に必要な参照先・スクリプトを読む。Claude 専用のツール名、hooks、`$CLAUDE_PROJECT_DIR` などへの依存を確認する。単なる Claude への言及だけで除外しない。
2. Codex でそのまま使えるスキルは個別にリンクする。移植が必要なら、両者で意味が通る小さな変更にする。大きな変更になる場合は理由と対応案を伝える。
3. 実パスを確認してから、存在しない共有先だけに `ln -s` する。`ln -f` は使わず、同名の別実体やリンク切れは上書きしない。同じ実体を参照済みなら何もしない。全設定へ影響する `make link` は共有だけのために実行しない。

```bash
# 例: リポジトリルートで、対象名と既存リンクを確認した後に実行
mkdir -p "$HOME/.agents/skills"
ln -s "$PWD/dotdir/.claude/skills/<対象名>" "$HOME/.agents/skills/<対象名>"
```

4. 確認スクリプトを再実行し、追加したリンクの `SKILL.md` と必要な参照先が読めることを確かめる。変更した対象・見送った理由・実際の一覧表示を確認していなければその点を報告する。権限外への書き込みには実行環境の承認手順を使う。

Codex 側だけにあるスキルを Claude に共有する依頼では、まずその実体を確認し、Claude のスキルディレクトリへ個別リンクする。同名の別実体を保護する原則は同じ。起動時の確認スクリプトは、この逆方向の未共有一覧を作らない。

## 配置

このスキル自体の正本も Claude のスキルディレクトリに置く。このリポジトリの `.agents/skills/share-claude-skills` は正本への相対リンクなので、ホーム側の設定を変更せず Codex から発見できる。他リポジトリでも使うと明示された場合だけ、ユーザー側の共有先にも配置する。

自作スキルを git に残す場合は `.gitignore` の個別 allowlist も確認する。未追跡のスキルを無断で追加・コミットしない。
