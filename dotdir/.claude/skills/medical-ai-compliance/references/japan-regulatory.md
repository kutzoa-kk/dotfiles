## 1. 薬機法・プログラム医療機器（SaMD）

### 1.1 概要

| 項目 | 内容 |
|------|------|
| 法令名 | 医薬品、医療機器等の品質、有効性及び安全性の確保等に関する法律（薬機法） |
| SaMD 規制開始 | 2014年施行改正により、単体ソフトウェア（プログラム医療機器）が医療機器規制対象に |
| 審査機関 | 独立行政法人 医薬品医療機器総合機構（PMDA） |
| 一次情報 URL | https://www.pmda.go.jp/review-services/drug-reviews/about-reviews/devices/0048.html |

### 1.2 クラス分類と審査経路

医療機器リスク分類はクラスI〜IVの4段階。SaMD（プログラム医療機器）も同じ枠組みに従う。

| クラス | リスク | 主な経路 | 備考 |
|--------|--------|----------|------|
| **クラスI** | 最低リスク | 届出（製造販売届） | 承認・認証不要。製造販売業許可は必要 |
| **クラスII** | 低〜中リスク | 登録認証機関による認証（認証基準あり）または大臣承認（認証基準なし） | 第三者認証機関が審査 |
| **クラスIII** | 中〜高リスク | 登録認証機関による認証（認証基準あり）または大臣承認（認証基準なし） | PMDA審査を経た大臣承認が基本 |
| **クラスIV** | 最高リスク | 大臣承認（必須） | PMDA審査必須。認証基準による簡略経路なし |

> **実装メモ（後続タスク向け）**: `assets/samd-risk-worksheet.md`（Task 8）はこの表のクラスI〜IVを参照する。クラス表記は「クラスI」「クラスII」「クラスIII」「クラスIV」で統一すること。

### 1.3 QMS 適合性調査

- クラスII〜IVの製造販売承認申請には、QMS（Quality Management System）適合性調査が必要
- 調査は PMDA または都道府県が実施
- ISO 13485 への適合が実質的な基準となる（薬機法 QMS 省令と整合）

## 2. 3省2ガイドライン（医療情報安全管理）

「3省2ガイドライン」は、厚生労働省・経済産業省・総務省が各々の役割に基づき策定した2本の医療情報安全管理ガイドラインの総称。医療機関（厚労省 GL）と IT 事業者（経産省・総務省 GL）の役割分担を明確化している。

### 2.1 厚生労働省ガイドライン

| 項目 | 内容 |
|------|------|
| 正式名称 | 医療情報システムの安全管理に関するガイドライン |
| 版 | 第6.0版 |
| 発行年月 | 令和5年（2023年）5月 |
| 発行機関 | 厚生労働省 |
| 対象 | 医療機関等（病院・診療所・薬局等、医療情報を扱う機関） |
| 一次情報 URL | https://www.mhlw.go.jp/stf/shingi/0000516275_00006.html |

**主要な要求事項（概要）**:
- 医療情報システムの安全管理責任体制の整備
- アクセス管理・認証・ログ管理
- 外部委託（クラウド・SaaS 利用）時の事業者要件の確認義務
- インシデント対応・BCP（業務継続計画）

> **未確認注記**: 第6.1版については草案の存在は確認されているが、正式発行日・正式名称・URL は本ドキュメント作成時点で未確認。第6.1版を参照する場合は一次情報（上記 URL のページ）で最新版を確認すること。

### 2.2 経済産業省・総務省ガイドライン

| 項目 | 内容 |
|------|------|
| 正式名称 | 医療情報を取り扱う情報システム・サービスの提供事業者における安全管理ガイドライン |
| 版 | 第2.0版 |
| 制定 | 令和2年（2020年） |
| 最終改定 | 令和7年（2025年）3月28日 |
| 発行機関 | 経済産業省・総務省 |
| 対象 | 医療情報を取り扱う IT・クラウドサービス事業者 |
| 一次情報 URL | https://www.meti.go.jp/policy/mono_info_service/healthcare/teikyoujigyousyagl.html |

**主要な要求事項（概要）**:
- サービス提供事業者としての安全管理義務
- クラウドサービス提供における医療情報の取り扱い要件
- 医療機関との契約・責任範囲の明確化
- 医療機関が厚労省 GL を遵守できるよう支援する義務

### 2.3 役割分担

| 役割 | 適用 GL | 主体 |
|------|---------|------|
| 医療情報システムの利用・管理 | 厚労省 GL（第6.0版） | 医療機関等 |
| 医療情報システム・サービスの提供 | 経産省・総務省 GL（第2.0版） | IT/クラウド事業者 |

> **実装判断の指針**: AI 医療支援ソフトウェアを SaaS として医療機関に提供する場合、開発・提供事業者は **経産省・総務省 GL** の要求を満たす必要がある。医療機関自身が内製・利用する場合は **厚労省 GL** が直接適用される。

## 3. DASH for SaMD

### 3.1 文書情報

| 項目 | 内容 |
|------|------|
| 名称 | DASH for SaMD（DX (Digital Transformation) Action Strategies in Healthcare for SaMD） |
| 発行年月 | 令和2年（2020年）11月 |
| 発行機関 | 厚生労働省 |
| 審査機関 | PMDA |
| 一次情報 URL（名称出典） | https://www.mhlw.go.jp/content/11124500/000761870.pdf |
| 一次情報 URL（相談窓口） | https://www.pmda.go.jp/review-services/f2f-pre/strategies/0011.html |

### 3.2 目的と主要施策

DASH for SaMD は、SaMD（プログラム医療機器）の開発・承認を促進するための総合的な施策パッケージ。

**主な施策**:

1. **SaMD 総合相談窓口の設置**: PMDA 内に SaMD 専門の相談窓口を設置。承認申請前の早期相談（Pre-Sub 相当）が可能
2. **審査体制の強化**: SaMD に精通した審査員の育成・配置
3. **ガイダンスの整備**: SaMD の承認申請に必要な資料・データに関するガイダンス文書の充実
4. **国際連携**: IMDRF 等との国際調和の推進

> **活用指針**: 新規 SaMD の薬機法承認を検討する段階で、PMDA への事前相談（DASH 窓口活用）を強く推奨する。特に AI/ML を用いた診断支援ソフトウェアは審査経路・必要データが不明確な場合があり、早期相談が実質的に必須。

## 4. IDATEN（変更計画確認手続制度）

### 4.1 文書情報

| 項目 | 内容 |
|------|------|
| 制度名 | 変更計画確認手続制度 |
| 通称 | IDATEN |
| 審査機関 | PMDA |
| 対象 | 承認を受けた医療機器（プログラム医療機器を含む）の市販後変更 |
| 国際的対応 | PACMP（Post-Approval Change Management Protocol）相当 |
| 一次情報 URL | https://www.pmda.go.jp/review-services/drug-reviews/about-reviews/devices/0039.html |

> **名称由来**: IDATEN は「韋駄天」（仏教の俊足の神）に由来することが確認されている。英語頭字語としての公式定義は **未確認**。公式文書で英語展開形が必要な場合は上記 URL の一次情報を参照すること。

### 4.2 制度の概要

IDATEN は、AI/ML ベースの SaMD における継続的な改善（追加学習・RWD（実臨床データ）による性能改善等）に対応するための変更管理制度。

**仕組み**:

| ステップ | 内容 |
|----------|------|
| ① 変更計画の事前承認 | 将来行う予定の変更の計画（範囲・評価方法・基準）を PMDA に事前提出し承認を受ける |
| ② 計画内変更の実施 | 承認された計画の範囲内で変更を実施 |
| ③ 軽微変更届出 | 計画内の変更は「軽微変更届出」として届出のみで完結（再承認不要） |
| ④ 計画外変更 | 事前承認計画の範囲を超える変更は通常の一部変更承認申請が必要 |

**AI/ML SaMD への適用**:

- **追加学習・継続学習**: 学習データの更新・追加による性能変化を変更計画に組み込める
- **RWD（Real-World Data）活用**: 市販後に収集した実臨床データを用いた性能改善
- **アルゴリズム更新**: あらかじめ定義した性能基準・評価指標の範囲内でのアルゴリズム変更

> **国際比較**: 海外規制との比較詳細は `international-regulatory.md` を参照すること。

## 5. 制度間の関係

```
薬機法
├── 承認前: クラス分類 → 審査経路決定
│               ├── クラスI:   届出のみ
│               ├── クラスII/III: 認証（基準あり）or 承認（基準なし）
│               └── クラスIV:  大臣承認必須
│
├── 承認プロセス支援: DASH for SaMD（早期相談窓口）
│
├── 市販後変更管理: IDATEN（変更計画確認手続）
│               └── 計画内変更 → 軽微変更届出（再承認不要）
│
└── 情報セキュリティ要件
    ├── 医療機関側: 厚労省 GL 第6.0版
    └── 事業者側:  経産省・総務省 GL 第2.0版
```
