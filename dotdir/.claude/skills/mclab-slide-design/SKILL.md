# MCLab スライドデザイン

膝OAデータ取得計画で使用した書式を、別テーマの計画・比較・データ説明にも再利用するためのデザインスキルです。配色だけでなく、編集可能なマスター、レイアウト、表、余白、文字階層を引き継ぎます。

## 使用する資産

- [参照PPTX](assets/reference.pptx)：共通マスター1種類、レイアウト12種類、構成例・編集ガイド14ページ。
- [表紙プレビュー](assets/preview.png)：参照PPTXの1ページ目です。完成物への貼り付け用画像ではありません。
- [デザイン仕様](references/design-system.md)：作成・デザイン変更時に読み、配色、文字、編集範囲を確認します。
- [レイアウト一覧](references/layout-guide.md)：構成を選ぶときに読みます。使わない構成例を完成物へ含める必要はありません。
- [デザイントークン](assets/design-tokens.json)：プログラムで配置やテーマを扱う場合に読みます。座標は96 dpiのpx、文字サイズはptです。
- [描画確認スクリプト](scripts/render-check.sh)：出力したPPTXを全ページ画像化します。

## 作成・編集

新規作成時は参照PPTXの作業用コピーを作り、内容に近い構成例を複製して置き換えます。参照ファイル自体は変更しません。既存資料の統一では、ユーザーの内容、表データ、注記を維持しながら、このデザインへ合わせます。

- タイトル、本文、結論帯、脚注の階層を維持します。長いタイトルには専用レイアウトを使い、文字を過度に小さくする前にページを分けます。
- 表はPowerPointの表機能を使います。既存の表を複製すると独自書式を保持できます。行数が変われば列幅・行高も見直します。
- 主要色と日本語・英数字フォントはテーマ設定を使います。淡い背景色は固定色のため、テーマ変更時には必要に応じて併せて調整します。
- 共通ヘッダーは初期状態の空欄を維持し、ユーザーが指定した場合のみマスターに入力します。eRubberやAI Smart Insole Cloudなどの固定名を追加しません。
- ページ番号のフィールド、プレースホルダーの種類・index、マスターとレイアウトの参照関係を維持します。
- 説明は日本語を基本とし、装飾目的の英語ラベルを増やしません。

## 編集の実行手順

PPTXはZIP書庫です。展開してスライドのXMLを書き換え、再圧縮する方法が、マスター・レイアウト・テーマ・ネイティブ表・ページ番号フィールドを最も確実に保持できます。専用ライブラリは不要です。

```
cp <skill>/assets/reference.pptx work.pptx        # 参照ファイルは変更しない
mkdir unpacked && cd unpacked && unzip -oq ../work.pptx
# ppt/slides/slideN.xml の <a:t> を書き換える
zip -q -X -r ../out.pptx '[Content_Types].xml' _rels docProps ppt
```

再圧縮では最上位の項目を漏らさず含めます。`[Content_Types].xml` を落とすとファイルが開けなくなります。

利用環境にPowerPoint作成・編集用のスキルやライブラリ（python-pptx、pptxgenjs など）がある場合は、それを併用しても構いません。いずれの場合も、PPTXのネイティブな図形、文字、表、マスターを保持できる手段を選びます。

構成例のページを複製して増やす場合は、`ppt/slides/` へXMLを追加するだけでは足りません。`ppt/_rels/presentation.xml.rels`、`ppt/presentation.xml` の `<p:sldIdLst>`、`[Content_Types].xml`、複製元スライドの `_rels` を併せて更新します。ページを増やさず置き換えるだけの編集より手間がかかるため、必要なページ数に近い構成例を選ぶことを優先します。

## 内容と確認

構成例の数値・計画は架空です。医療の条件、対象人数、段階名、施設区分、性別割合などを新しい資料の要件として流用しません。実際の内容と出典は今回の依頼・提供資料から取得します。ユーザーが別の構成やデザインを指定した場合は、その指定を優先します。

出力したPPTXの全ページを描画し、文字の欠け、はみ出し、表の可読性、背景・色・フォント、ページ番号を確認します。表が画像化されていないことと、マスター・レイアウト・テーマが残っていることも検証します。未検証のアプリ動作を確認済みと報告しません。

```
<skill>/scripts/render-check.sh out.pptx ./render
```

スクリプトには実行権限が付いています。`sh` や `bash` を前置せず、パスをそのまま実行します。生成された `render/page-*.png` を全ページ読み込んで目視で確認します。macOSでは日本語がHiragino Sansで描画されます。英数字のRobotoが未導入の環境では代替フォントに置き換わるため、その旨を明示して報告します。

LibreOfficeへ `-env:UserInstallation=...` で一時プロファイルを渡すと、Hiragino Sansが解決されず日本語が全て豆腐（□）になります。描画確認スクリプトはこの指定を使いません。手動で `soffice` を呼ぶ場合も同様に、既定プロファイルのまま実行します。
