# chatgpt-bridge 既定モデル設計（GPT-5.6）

- 日付: 2026-07-15
- 対象スキル: `dotdir/.claude/skills/chatgpt-bridge`
- 背景の位置づけ: この設計記録は、既存の `2026-06-30-chatgpt-bridge-design.md` に**存在しなかった**「リーズニングモード選択」機構の設計を事後的に補うもの。当該機構は spec 更新（2026-07-06）後にライブ検証ベースでスキル実体へ追記され、設計記録が無かった。

## 決定事項

ChatGPT Pro のモデル刷新（`GPT-5.5` 廃止、`GPT-5.6` 追加）に伴い、chatgpt-bridge の**既定モデルを `GPT-5.6` に変更**する。かつ既定挙動を「モードを触らない」から「**既定で `GPT-5.6` を選択**」へ変更する（ユーザー選択＝既定で自動選択）。

## 変更前後の挙動

| 状況 | 変更前 | 変更後 |
|---|---|---|
| モード未指定 | §0 をスキップ＝現在選択中のモードをそのまま使う | §0 を必ず実行し、既定モデル `GPT-5.6` を選択 |
| モード明示（「Pro拡張で」等） | その指定に従う | 変更なし（明示が優先） |
| 既に `GPT-5.6` | — | 早期 return でクリック0回（余計な操作なし） |
| `GPT-5.6` がメニューに無い | — | fail-loud（送信せずユーザー報告） |

## 設計上の要点

1. **既存ロジックの再利用**: §0 の選択スニペットには既に「現在が `want` と一致なら早期 return」ガードと「メニューに無ければ fail-loud」がある。既定 `want` を `GPT-5.6` にして §0 を常時実行に切り替えるだけで、追加ロジックはほぼ不要。
2. **ドリフト対策（単一の真実）**: 既定モデルを選択スニペット冒頭の `DEFAULT_MODE = "GPT-5.6"` 1箇所で管理する。モデル名は頻繁にドリフトする（例: Sol/Luna/Terra 追加、5.5→5.6）ため、ハードコードの分散を避ける。移行時はこの1行のみ変更。
3. **UI 構造の不確実性の吸収**: モデル選択が推論強度（最速/標準/高/最高）と同一メニューか別ドロップダウンかは実機未確認。スキル自身の「実行時列挙 + fail-loud」で吸収し、`GPT-5.6` が見つからなければ推測で送信しない。
4. **安全原則との整合**: 余計なセレクタ操作は増えない（既に `GPT-5.6` なら innerText 照合のみ）。ユーザーの明示指定は常に優先。利用上限・レート制限への配慮、重いモードの 600s+ タイムアウトは現状維持。

## 検証方針

- 静的: JS スニペットの構文健全性（`DEFAULT_MODE`/正規表現）を node で確認。
- 実機: ライブ検証（デバッグ Chrome :9222）は本更新時点で不可。次回スキル使用時に §0 実行時列挙が `GPT-5.6` の実在と正確な表示ラベルを確認し、fail-loud で誤モデル送信を防止する。
