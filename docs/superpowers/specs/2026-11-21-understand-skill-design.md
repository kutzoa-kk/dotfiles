# /understand スキル（自分用）の設計

## 目的

Claude の説明が分からないとき、いまの会話を汚さずに付箋で聞き返せるようにする。あわせて、分からなかった文を記録し、Claude の普段の書き方を直していく。場面は論文の解析・dotfiles の作業など、すべて。

## 目指すこと・目指さないこと

- 目指す：分からない文をその場で聞き返せる。聞き返した結果が、書き方の決まり（`japanese-style-guide.md`）に戻る。
- 目指さない：参考のスキルの画面や機能を作り直すこと。Codex・agy との共有（分身の仕組みが Claude Code 専用のため）。
- 失敗とみなすこと：決まりに、中身が難しかっただけの文まで足されて、決まりが膨らむこと。

## 前提と制約

- 土台は fkubota/understand-mode（MIT ライセンス、コミット `89ebc91`）。Node 18 以上が要る（手元は v22）。
- `~/.claude/skills` は dotfiles の `dotdir/.claude/skills` へのリンクなので、スキルは dotfiles の中に置く。容量は約6.5MB（大半は図を描く部品）。

## 作り方の候補

| 案 | 内容 | 判断 |
| --- | --- | --- |
| 1 | 参考のスキルをそのまま入れる | 速いが、本人向けの工夫が入らない |
| 2 | 参考のスキルを写し、分からなかった文を記録する仕組みを足す | **採用**（本人が選択） |
| 3 | 画面なしの小さな版を一から作る | 付箋で選ぶ使い心地がない |

## 本人が決めたこと

- 案2で作る。

## 中身

1. 参考のスキル（`skill/understand/`）を `dotdir/.claude/skills/understand/` へ写す。ライセンスも写す。
2. 画面：「メインに送って閉じる」のとき、種類が「質問」「詳しく」「用語」の付箋を集めて送る。1枚ごとに、元の文・最初の質問・最後の回答の冒頭を含める。本人が押すボタンは増やさない。
3. サーバー：`/api/return` で受け取った記録を `<DIR>/confusions.json` に書く。
4. スキル本体（`SKILL.md`）の「終わった」と言われた後の手順に、次を足す。
   - `confusions.json` を読み、文ごとに「言い方が悪かった」か「中身が難しいだけ」かを仕分ける。
   - 言い方が悪かったものは、`japanese-style-guide.md` の育て方に従って対応表に1行足す。同じ指摘の行がすでにあれば、その行を強めて日付を更新する。
   - 何を足したかを本人に報告する。確認は挟まない（決まりのファイル自体が「応答の前に1行足す」と定めているため。git で戻せる）。
5. 付箋のやり取りは参考のスキルと同じく閉じたら消す。残るのは決まりに足した行だけ。

## 作る人に任せること（Claude の判断）

- 子付箋（付箋の回答の中の文から作ったもの）も集める。分身の説明も Claude の書き方なので。
- グラフの点から作った付箋（元の文が「グラフの値：」で始まるもの）は集めない。言い方の問題ではないため。
- 回答の冒頭は500字までにする。言い換えの要点をつかむには足り、記録が膨らまない。
- 確認は dotfiles の既存の試験（`.bin/tests` の Python の試験と `make` の入口、CI）に足す。参考のスキルの開発用フォルダ（`dev/`）は写さない。
