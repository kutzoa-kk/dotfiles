# 日本語出力の品質安定化システム — 設計書

- **作成日**: 2026-06-30
- **対象**: グローバル（`~/.claude/` 配下、全プロジェクト適用）
- **状態**: 実装済み・運用中（japanese-output-review スキル + japanese-style-guide.md の育成運用が稼働。2026-07-06 更新）

## 1. 背景と目的

Claude Code の日本語出力が不安定で、以下の症状が出ている。

- 不要な英語の混入（地の文に `Let me...` `First,` `Note that` 等、技術用語以外の英語）
- 文体の乱れ（です/ます体の不統一）
- 「わかりづらい表現」の繰り返し（同じ不適切な言い換えが再発する）
- 出力崩壊（前セッションで、ツール呼び出しマークアップ＝`invoke`/`parameter` タグが地の文へ混入する事象が発生）

CLAUDE.md には既に「言語：日本語(技術用語は英語)」「敬語統一」ルールがあるが、それでも崩れている。**ルール追記だけでは不十分**であり、(a) フィードバックを蓄積する記録、(b) それを常時参照する仕組み、(c) 明示的にレビューする手段、の3点が必要。

## 2. 設計判断の記録

ブレインストーミングで以下を確定した。

| # | 論点 | 決定 | 理由 |
|---|------|------|------|
| 1 | 是正の強度・タイミング | **予防中心（記録を常駐）** | 副作用なし・軽量。書く前に守る。効果を見てから hook を追加できる（YAGNI） |
| 2 | フィードバックの記録起点 | **指摘を検知したら即記録** | 漏れが最も少ない。指摘されたその場で捕捉する |
| 3 | レビュー対象 | **直前/最近の Claude 応答が主** | ユーザーの困りごと（Claude 出力の不安定さ）へ直接対応。指定テキストにも対応可 |
| 4 | 記録ファイルの配置 | **CLAUDE.md と同階層**（`dotdir/.claude/`） | `@RTK.md` と同じ実績ある手法。パス解決が確実。git 管理で蓄積履歴が資産化 |

### 設計上の重要な気づき

- **スキルは常時ロードされない**（特定トリガー時のみ）。「全出力で英語が混じる」は*常時*の問題なので、予防と検知の「号令」はトリガー型スキルではなく **CLAUDE.md 常駐ルール**に置く必要がある。
- スキルには「重い分析（レビュー）」と「一括記録・重複整理」という*別の仕事*を担わせる。
- 記録フォーマットを**1行1エントリ**に単純化することで、即記録が「CLAUDE.md の号令＋その場で1行追記」で完結し、重いスキル起動が不要になる。

## 3. アーキテクチャ（3コンポーネント）

```
┌─ ① CLAUDE.md 常駐ルール（数行追記）──────────────┐
│   予防の号令：出力時は記録の禁止表現を避け推奨表現を使う │
│   検知の号令：表現への不満を見たら記録へ1行追記してから応答 │
└────────────┬───────────────────────────────────┘
             │ @japanese-style-guide.md で常駐
┌─ ② 記録ファイル japanese-style-guide.md ─────────┐
│   禁止→推奨の対応表（1行1エントリ・理由付き）       │
│   一般ルール（英語混入の線引き／文体／崩壊出力の禁止） │
└────────────┬───────────────────────────────────┘
             │ 参照 & 追記
┌─ ③ スキル japanese-output-review ────────────────┐
│   直前応答（or 指定テキスト）をレビュー             │
│   違反を HTML/Markdown で可視化                     │
│   発見した問題・確定した言い換えを ② に一括追記       │
└────────────────────────────────────────────────┘
```

**責務の分離**：常時効く号令は CLAUDE.md、データは記録ファイル、重い分析は明示起動のスキル。各々が単一責務で独立に理解・変更・テストできる。

## 4. 各コンポーネント詳細仕様

### ① CLAUDE.md 常駐ルール

`dotdir/.claude/CLAUDE.md` の `## 基本情報`（言語ルール）付近に、以下の趣旨を数行で追記する。

- **予防**：日本語出力時は `@japanese-style-guide.md` の禁止表現を避け、推奨表現を使う。
- **検知**：ユーザーが表現へ不満・言い換え要望を示したら、応答の前に `japanese-style-guide.md` へ1行追記する。
- ファイル末尾の `@RTK.md` の隣に `@japanese-style-guide.md` を追加して常駐させる。

CLAUDE.md 本体は薄く保ち、詳細（線引き・具体例）は記録ファイル側に置く。

### ② 記録ファイル `japanese-style-guide.md`

配置：`dotdir/.claude/japanese-style-guide.md` → `make link` で `~/.claude/japanese-style-guide.md`（実証済み: link.sh 226行で直下ファイルは無条件リンク）。

構成：

```markdown
# 日本語スタイルガイド（記録・育成ファイル）

## 一般ルール
- 文体：です/ます体で統一。結論ファースト、前置き不要。
- 英語混入の線引き：
  - 許可：コード識別子（変数/関数/ファイルパス）、確立した技術用語（API, git, commit, hook, MCP 等）、製品名・固有名詞
  - 禁止：日常語の英語化（Let me, First, Note that, OK 等を地の文に）、理由なきカタカナ英語、英文の地の文
- 崩壊出力の禁止：ツール呼び出しマークアップ（invoke/parameter タグ）を地の文に書かない。

## 禁止→推奨 対応表（フィードバックで育つ）
<!-- 形式: - ❌ 禁止表現 → ✅ 推奨表現（理由 / 日付） -->
（初期は空。一般ルールでカバーし、対応表はフィードバックで育てる）
```

1行1エントリの単純形式により、即記録時の追記が容易。

### ③ スキル `japanese-output-review`

配置：`dotdir/.claude/skills/japanese-output-review/SKILL.md`（`references/` にレビュー観点の詳細を分離可能）。

frontmatter（既存スキルに倣い `name` + `description`、トリガー語と Do NOT trigger を明記）：

- トリガー例：「日本語チェックして」「今の出力レビューして」「日本語の品質見て」「文体チェック」「review my Japanese」
- Do NOT trigger：英文の校正、翻訳、コードレビュー、Markdown/HTML の体裁のみの整形

**レビュー観点（チェック項目）**:
1. 不要な英語混入（②の線引きに照らす）
2. 文体の乱れ（です/ます体の不統一、敬語崩れ）
3. 記録済み禁止表現の使用（②の対応表と照合）
4. わかりにくい表現（直訳調・冗長・曖昧）
5. 崩壊出力（ツールマークアップ混入等）

**出力形式（内容量で自動判定）**:
- **Markdown（軽量）**：違反箇所のチェックリスト＋推奨置換。数件程度のときの既定。
- **HTML（詳細レポート）**：違反ハイライト＋カテゴリ別集計＋推奨置換表＋記録への反映候補。`html-report-generator` スキルを活用。件数が多い/共有したいときに使用。

**仕上げ**：レビューで発見した問題・確定した言い換えを ② の対応表へ一括追記（重複チェック・カテゴリ整理を含む）。

## 5. データフロー（3シナリオ）

1. **予防（毎回）**：`@japanese-style-guide.md` が常駐 → Claude が書く前に禁止表現を避ける。
2. **即記録（指摘時）**：ユーザー「〜はわかりづらい」→ CLAUDE.md 号令により、応答前に記録へ `❌旧 → ✅新（理由/日付）` を1行追記 → 次回から予防が効く。
3. **レビュー（明示時）**：「日本語チェックして」→ スキル起動 → 直前応答を5観点で点検 → HTML/MD で可視化 → 記録へ一括反映。

## 6. 配置とリンク（実証済みの事実）

- `~/.claude/CLAUDE.md` は `dotdir/.claude/CLAUDE.md` へのシンボリックリンク（編集が即反映、@参照の起点）。
- link.sh の `.claude` 処理：直下ファイルは無条件リンク（226行）、ディレクトリは `LINK_DIRECTORIES=(commands agents scripts assets skills rules)` のみリンク（203行）。
- したがって：記録ファイル（直下 .md）もスキル（skills/ 配下）も `make link` で正しく `~/.claude/` に展開される。
- 注：`~/.claude/RTK.md` は実体ファイル（dotfiles 管理外）。本記録ファイルは dotdir 配置・git 管理とし、蓄積履歴を資産化する。

## 7. 検証方法

- **正例**：記録に既知の禁止表現を1件入れ、レビュースキルがそれを検出するか。
- **負例**：技術用語（`git`, `API`, ファイルパス等）を誤検知しないか。
- **即記録**：模擬指摘 → 記録ファイルへ1行追記が行われるか。
- **@参照の常駐**：`make link` 後、CLAUDE.md の `@japanese-style-guide.md` がコンテキストにロードされるか（新セッションで確認）。
- **HTML出力**：詳細レポートが `html-report-generator` で生成され、ブラウザで表示できるか。

## 8. スコープ外（YAGNI）

- **Stop hook による自動検知**：今回は予防中心のため作らない。効果を見てから将来追加可能（設計上の拡張点として残す）。
- **英文・多言語の校正**：日本語出力に限定。
- **CI/自動テスト化**：手動検証で開始。
