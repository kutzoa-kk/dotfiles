## High（5件）

### SF-01 — 有効プラグイン39個が常駐スキル説明を大量注入
- **evidence**: `~/.claude/plugins/installed_plugins.json` の plugins キーは39個（code-simplifier, context7, ecc, octo, superpowers, academic-research-skills 他）。プラグイン由来の重複排除後スキルは406個・説明文合計92,139文字（約23,034トークン）が常駐予算を消費。
- **recommendation**: 未使用プラグイン（aws-serverless=20, data-engineering=25, academic-research-skills など特定ドメイン専用）を無効化し、常駐スキル数を実利用分へ絞る。

### SF-02 — ecc プラグイン単独で全スキル予算の6割超を占有
- **evidence**: `~/.claude/plugins/cache/ecc/ecc` 配下の distinct SKILL.md は262個、説明文合計57,234文字（約14,308トークン）。プラグイン由来スキル総数406個のうち65%、説明文予算の62%を ecc 1プラグインが消費。
- **recommendation**: ecc の巨大スキルセットを常駐させる必要があるか再評価。必要なサブセットのみ有効化する仕組み（スコープ限定・無効化）を検討。

### DUP-01 — ブラウザ自動化 MCP が4系統並存＋組込
- **evidence**: (1) `~/.claude.json` mcpServers の `chrome-cdp`（npx chrome-devtools-mcp@latest）→ `mcp__chrome-cdp__*`（約26 tool）; (2) 有効プラグイン ecc の `.mcp.json` が `chrome-devtools` を登録 → `mcp__plugin_ecc_chrome-devtools__*`（約26）; (3) chrome-devtools-mcp プラグイン → `mcp__plugin_chrome-devtools-mcp_chrome-devtools__*`（約26）; (4) playwright プラグインの `playwright`。加えて組込 `mcp__claude-in-chrome__*`（約20）。ブラウザ自動化だけで実質4 MCP + 1組込 = 約100 tool 超。
- **recommendation**: 1系統へ集約。chrome-devtools 系の3重登録（chrome-cdp・ecc・chrome-devtools-mcp）を優先解消。

### DRIFT-001 — CLAUDE.md が @import する RTK.md が git に存在しない
- **evidence**: `dotdir/.claude/CLAUDE.md:66` に `@RTK.md` の import があるが `dotdir/.claude/RTK.md` は存在せず（MISSING）、git ls-files でも未追跡。実体は `~/.claude/RTK.md` に REGULAR FILE として存在するのみ。fresh clone + make link では RTK.md が欠落し import が壊れる。
- **recommendation**: `~/.claude/RTK.md` を `dotdir/.claude/` へ移動して git 追跡下に置き merge リンク対象に含める。または CLAUDE.md の @RTK.md 参照を削除。

### DRIFT-002 — settings.json が独立実体で git 版と大幅乖離
- **evidence**: `~/.claude/settings.json` は REGULAR FILE（symlink ではない）。稼働397行 vs git 318行（+79）。稼働側のみに: (1) orca 注入 hooks（PreToolUse/Stop/StopFailure に `~/.orca/agent-hooks/claude-hook.sh`）、(2) enabledPlugins ブロック（約30プラグイン）、(3) extraKnownMarketplaces（nam-tech-studio 等）。make link で同期されず恒久乖離。
- **recommendation**: orca 注入の動的キー（hooks/enabledPlugins/marketplaces）と git 管理の静的設定の切り分け方針を決める。

## 試走の技術メモ（設計へのフィードバック）

1. **args の JSON 文字列化**: Workflow ランタイムが `args` を JSON 文字列で渡す場合があり、`args.date` が `undefined`（→ `date: "unset"`）になった。3 Workflow スクリプトを `const A = typeof args === 'string' ? JSON.parse(args) : (args ?? {})` で両対応に修正済み。
2. **name 起動のキャッシュ**: `Workflow({ name: 'env-audit' })` は起動時登録済みワークフローのみ解決するため、セッション中に追加したファイルは名前で拾えない。当面は `scriptPath` 起動、`name` 起動は次回セッションから有効になる見込み。
3. **所見の質**: 手動調査で発見した地雷（settings 乖離・RTK.md 欠落・ブラウザ4系統・ecc 62%）を Workflow が自力で再発見。指示文の環境知識（COMMON プロンプト）が機能している。
