### DRIFT-001 — 稼働中 settings.json に git 未追跡の重要キーが多数存在

- **recommendation**: `docs/settings-ownership.md` の定義通り settings.json は git=種・稼働=ライブが正であれば、この差分自体は想定内の可能性が高い。ただし `enabledPlugins`・`extraKnownMarketplaces`・`model` 設定は環境の実態を左右する重要情報のため、`make settings-pull` を実行し git 側スナップショットを最新化することを推奨（現状 git 側は相当古い状態のまま放置されている）。

- **evidence**: `~/.claude/plugins/installed_plugins.json` の plugins キー数=30。`ecc@ecc` の installPath（`.../cache/ecc/ecc/2.0.0`）配下に `find -name SKILL.md` で865件（同 installPath 配下は 2.0.0 のみ存在するため実働数）。次点は `octo@nyldn-plugins`（9.47.1）107件、`chrome-devtools-mcp` 42件、`example-skills` 54件、`data-engineering` 25件、`aws-serverless` 20件。単純合計で1000件超のスキルがロード対象になっている。

### DUP-01 — chrome-devtools MCP がプラグイン2つで並存登録
- **evidence**: 有効化プラグイン一覧に `chrome-devtools-mcp@claude-plugins-official` と `ecc@ecc` が両方登録済み。前者の実体（`.../claude-plugins-official/chrome-devtools-mcp/1.5.0/.claude-plugin/plugin.json`）は `mcpServers.chrome-devtools = npx chrome-devtools-mcp@1.5.0`。後者の実体（`.../marketplaces/ecc/.mcp.json`）も同名 `mcpServers.chrome-devtools = npx chrome-devtools-mcp@latest` を登録。本セッションでも `plugin:ecc:chrome-devtools` 名で MCP ツールが connecting 中と表示されており、同一役割（Chrome DevTools 経由のブラウザ自動化）のサーバーが2経路（バージョン固定 1.5.0 と @latest）から二重に起動されうる状態。
- **recommendation**: （事実列挙のみ。採否判断はしない）

### DRIFT-002 — 稼働環境に orca 外部フックが注入されているが git 側に記録なし
- **evidence**: 稼働側 settings.json 行128, 296：`"command": "if [ -x '/Users/kkmclab/.orca/agent-hooks/claude-hook.sh' ]; then /bin/sh '/Users/kkmclab/.orca/agent-hooks/claude-hook.sh'; fi"` が `PostToolUse`（matcher `*`）と `StopFailure` に2箇所存在。git 側 `dotdir/.claude/settings.json` には同等の行が存在しない（diff 全体で orca への言及ゼロ）。
- **recommendation**: orca によるフック注入がユーザー承知の想定挙動か確認し、承知済みなら `make settings-pull` で git 側へ反映。未承知なら注入元（`/Users/kkmclab/.orca/agent-hooks/claude-hook.sh`）の由来を調査。
